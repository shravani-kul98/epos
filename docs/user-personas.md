# User Personas

## 1. Executive / PMO Lead — "Dana"
- **Role:** Owns portfolio governance and executive reporting.
- **Goals:** See which projects need attention this week; trust the underlying data;
  produce a credible weekly executive update quickly.
- **Frustrations:** Manual status collation; RAG status without explanation; stale data
  reported as fact.
- **Uses:** Portfolio Dashboard, Ask EPOS (weekly executive update), Change Impact (approval).
- **Success:** Can explain, with evidence, why any project is Green/Amber/Red.

## 2. Project / Programme Manager — "Alex"
- **Role:** Runs a single programme (e.g. Supplier Decarbonisation).
- **Goals:** Spot slipping milestones, blocked tasks, overdue actions and unowned risks early;
  understand the impact of a supplier delay before it becomes a crisis.
- **Frustrations:** Surprises at gate reviews; no quick way to model "what if the supplier
  slips 30 days?".
- **Uses:** Project Intelligence, Scenario Planner, early-warning alerts.
- **Success:** Acts on a Critical alert before it affects a release gate.

## 3. Requirements / Engineering Lead — "Priya"
- **Role:** Owns requirements quality, traceability and verification.
- **Goals:** Ensure every high-priority requirement is implemented, tested and verified before
  a release; understand what a change request (e.g. CR-042) affects.
- **Frustrations:** Requirements without tests; failed/absent verification evidence; unclear
  change impact across tasks, tests and milestones.
- **Uses:** Requirements Traceability, Change Impact.
- **Success:** No high-priority requirement reaches a release gate without verification evidence.
